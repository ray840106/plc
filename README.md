# 電梯 PLC 控制程式（IEC 61131-3 結構化文字 ST）

單台電梯的 PLC 控制程式，預設 **4 層**（參數可改 2～8 層），採用實際電梯常用的
**集選控制**（Selective-Collective）：同方向順路停靠、該方向沒有呼叫才反向。
程式使用國際標準 IEC 61131-3 的 **ST（結構化文字）** 撰寫，可直接用於
CODESYS、OpenPLC、Beremiz、Beckhoff TwinCAT 等，也可以照
[移植說明](#移植到其他廠牌-plc) 改到西門子、三菱等 PLC。

**三菱 FX3U 階梯圖版** 在 [fx3u/](fx3u/README.md)：同樣的功能改寫成 170 個梯級，
可直接看 [階梯圖](fx3u/LADDER.md)，I/O 為 X0~X27、Y0~Y27（FX3U-48M）。

程式已用 OpenPLC / Beremiz 同源的 matiec 編譯器編譯，並以電梯物理模型做
自動模擬測試（ST 版 45 項，FX3U 階梯圖跑同一套 4 層測試 42 項，含隨機乘客壓力測試），
見 [模擬測試](#模擬測試)。

> ⚠️ 本程式適用於教學、電梯模型與實驗台。真實載人電梯必須符合當地法規與標準
> （例如 EN 81-20/50；台灣另有建築技術規則、CNS 標準與定期安全檢查），
> 安全迴路、門鎖、極限開關、上下行接觸器互鎖都必須以**硬體**配線實現，
> 不可只依賴 PLC 程式。

## 功能

| 類別 | 功能 |
|------|------|
| 呼叫 | 車廂內各樓按鈕、各樓上/下呼叫按鈕、按鈕燈（服務後熄滅） |
| 集選控制 | 同方向順路停靠；反方向的呼叫等回程再停；前方沒呼叫才反向；待命時先去最近的呼叫 |
| 顯示 | 上/下行方向燈（開門時預告接下來的方向）、樓層 BCD 輸出（接 7 段解碼器）、樓層數值（HMI） |
| 門 | 自動開門、開門停留 3 秒、開門鈕延長/重開、關門鈕提早關、光電/安全觸邊重開、超載不關門並鳴蜂鳴器、關門逾時自動重開重試 |
| 安全 | 安全迴路（緊急停止）、上/下極限、門未關妥不運轉、運行中門鎖脫開即停、運行時間限制、樓層感測器順序檢查、上下行互鎖、起動/停車延遲 |
| 定位 | 上電時若不在樓層 → 關門後低速往下找樓層並開門；停車滑出平層區 → 低速再平層 |
| 故障 | 7 種故障碼、故障燈、故障時清除所有呼叫，按復歸鈕重新初始化 |

## 檔案結構

```
src/                         ← PLC 程式（依序放入專案）
  01_types.st                  資料型別：樓層陣列、狀態、方向
  02_FB_ElevatorCtrl.st        電梯控制功能塊（所有控制邏輯都在這裡）
  03_PRG_Elevator.st           主程式：實體 I/O 位址對應 + 呼叫功能塊
  04_config.st                 組態（10 ms 週期工作，OpenPLC / Beremiz 用）
docs/design.md               ← 控制邏輯詳細說明（狀態機、方向判斷、時序）
fx3u/                        ← 三菱 FX3U 階梯圖版（指令表、階梯圖、軟元件註解）
sim/                         ← 模擬測試（不需要放進 PLC）
```

`FB_ElevatorCtrl` 與硬體無關；換 PLC、換位址、改樓層數時通常只需要改
`PRG_Elevator`。

## 動作說明

1. **上電**：等 1 秒讓輸入穩定。車廂在某層平層區 → 待命；不在任何平層區
   → 先關門，再以低速往下找最近的樓層，到了就開門（若已壓到下極限則往上找）。
2. **呼叫**：按下按鈕即登記並亮燈，服務時熄滅。按目前所在樓層的按鈕會直接開門。
3. **集選控制**：
   - 往上運行時，停靠「車廂呼叫」與「上呼」的樓層；「下呼」等回程再停。
     往下同理。
   - 前方已沒有任何呼叫時，停在最遠的呼叫樓層並反向。
   - 待命（無方向）時先去最近的呼叫，距離相同先往上。
   - 例：車廂在 1F，有人在車廂按 4F；上行途中 3F 有人按「上」、2F 有人按「下」
     → 依序停 **3F → 4F → 2F**。
4. **方向燈**：開門時顯示電梯接下來要走的方向，等候的乘客可依此判斷要不要進入。
5. **門**：到站自動開門，停留 3 秒後關門。
   開門鈕、光電遮擋、超載、本層再按呼叫 → 延長開門或關門中重新打開；
   關門鈕可提早關門（有遮擋或超載時無效）。關門 8 秒仍關不上 → 重開再試，
   連續 3 次失敗 → 故障 7。
6. **運行**：門關妥後延遲 0.5 秒起動；到達要停的樓層（該層平層感測器 ON）
   立即停止，煞車穩定 0.5 秒後開門。若滑行超出平層區 → 反方向低速再平層。

詳細的狀態機與判斷規則見 [docs/design.md](docs/design.md)。

## 故障碼

| 碼 | 名稱 | 發生原因 | 復歸方式 |
|---|---|---|---|
| 1 | 安全迴路開路 | 緊急停止、安全迴路斷開 | 恢復後**自動**重新初始化 |
| 2 | 運行逾時 | 高速時相鄰兩層間超過 15 秒（低速 30 秒）仍未到達：馬達、皮帶或感測器故障 | 按復歸鈕 |
| 3 | 樓層感測器異常 | 多個平層感測器同時 ON、樓層順序錯誤（漏訊號）、停止中出現其他樓層、再平層 3 次仍失敗 | 按復歸鈕 |
| 4 | 超越極限 | 運轉中碰到上/下極限，或要起動的方向極限已動作 | 按復歸鈕 |
| 5 | 門鎖 / 門位置異常 | 運行中關門到位訊號消失，或開門到位與關門到位同時 ON | 按復歸鈕 |
| 6 | 開門失敗 | 開門 8 秒仍未到位 | 按復歸鈕 |
| 7 | 關門失敗 | 關門連續 3 次逾時（或找樓層前關門逾時） | 按復歸鈕 |

故障時：馬達與門機停止、清除所有呼叫、故障燈亮、不接受呼叫。
復歸後重新初始化，位置不明時會自動低速找樓層。

## 參數

在 `PRG_Elevator` 呼叫 `fbElevator(...)` 的地方修改：

| 參數 | 預設 | 說明 |
|---|---|---|
| `nNumFloors` | 4 | 樓層數 2～8 |
| `tDoorDwell` | T#3S | 開門停留時間 |
| `tDoorTimeout` | T#8S | 開門 / 關門動作逾時 |
| `tStartDelay` | T#500MS | 門關妥到馬達起動的延遲 |
| `tBrakeDelay` | T#500MS | 停車後的煞車穩定時間 |
| `tRunTimeout` | T#15S | 高速時相鄰兩層之間的最長運行時間 |
| `tSlowTimeout` | T#30S | 低速（找樓層、再平層）的最長運行時間 |
| `nDoorRetryMax` | 3 | 關門失敗次數上限 |

**改成其他樓層數**（例如 5 層）：把 `nNumFloors := 5`，並在 `PRG_Elevator`
增加 5F 的按鈕、感測器、燈號的位址與陣列對應（`aCarBtn[5]`、`aHallDnBtn[5]`、
`aFloorSensor[5]`、`Q_CarLamp5` …），頂樓沒有上呼、底樓沒有下呼。
超過 8 層時再把 `T_FloorBool` 的上限與 `MAX_FLOORS` 一起加大。

**掃描週期**：建議 10 ms（最長 20 ms）。車廂全速通過平層感測器的時間至少要有
2～3 個掃描週期，例如速度 1 m/s、週期 10 ms，感測區長度至少約 30 mm。

## 使用方式

### OpenPLC / Beremiz
把 `src/` 的四個檔案依序合併成一個 `.st` 檔，上傳到 OpenPLC Runtime
（Programs → Upload Program）。I/O 位址請依你的硬體調整 `PRG_Elevator`。

```bash
cat src/01_types.st src/02_FB_ElevatorCtrl.st src/03_PRG_Elevator.st src/04_config.st > elevator.st
```
Windows：
```bat
copy /b src\01_types.st+src\02_FB_ElevatorCtrl.st+src\03_PRG_Elevator.st+src\04_config.st elevator.st
```

### CODESYS（及 TwinCAT 等以 CODESYS 為基礎的軟體）
1. 新增 DUT：`T_FloorBool`（別名 Alias）、`E_ElevState`、`E_Dir`（列舉），內容照
   `01_types.st`。列舉若自動加上 `{attribute 'qualified_only'}`，請刪除這一行
   （本程式直接寫 `DIR_UP`，不寫 `E_Dir.DIR_UP`）。
2. 新增 POU `FB_ElevatorCtrl`（功能塊，ST）：`FUNCTION_BLOCK` 到最後一個 `END_VAR`
   貼到宣告區，其餘（不含 `END_FUNCTION_BLOCK`）貼到程式區。
3. 新增 POU `PRG_Elevator`（程式，ST），同樣分成宣告區與程式區。
4. 在 Task Configuration 把 `PRG_Elevator` 加到 10 ms 週期的 MainTask。
   `04_config.st` 不需要。

### 移植到其他廠牌 PLC
`FB_ElevatorCtrl` 只用到標準 ST 語法，移植時注意：

| 項目 | 本程式 | 移植方式 |
|---|---|---|
| 列舉 | `E_ElevState`、`E_Dir` | 不支援列舉型別的軟體（例如西門子 SCL）改成 INT 常數，CASE 標籤改用數字並加註解 |
| 陣列型別 | `T_FloorBool` | 直接宣告 `ARRAY[1..8] OF BOOL` |
| 常數 | `VAR CONSTANT` | 改成該軟體的常數或直接寫數值 |
| 計時器 | `TON`、`R_TRIG` | 使用該軟體的 IEC 標準計時器 / 上升緣功能塊（西門子為多重背景 `#tonState(...)`） |
| I/O 位址 | `%IX0.0` / `%QX0.0` | 依上方 I/O 表改成 X0 / Y0、I0.0 / Q0.0 等 |
| 變數存取 | `eState` | 西門子 SCL 區域變數要加 `#` |

只能寫階梯圖的機種，可以參考 [三菱 FX3U 階梯圖版](fx3u/README.md)：
每個狀態用一個輔助繼電器（M 點），每條轉移條件寫成一個「SET 下一狀態 / RST
本狀態」的梯級，其他廠牌的階梯圖也可以照同樣結構改寫。

## 模擬測試

`sim/` 用 matiec 把 **同一份 ST 程式** 編譯成 C，再用 Python 模擬車廂、門與
感測器，以 10 ms 掃描週期驅動 PLC 程式；FX3U 階梯圖則由 `sim/fx3u.py`
（FX3U 指令表模擬器）執行，接上同一個物理模型。每次掃描都檢查安全條件：

- 上升/下降、開門/關門不會同時輸出
- 門沒有完全關閉時馬達不會運轉
- 車廂移動中或不在平層區時不會開門
- 車廂不會超出極限位置；BCD 樓層顯示正確

測試項目（ST 版 45 項，其中 4 層的 42 項 FX3U 階梯圖也各跑一次）：一般運轉與集選順序、方向預告、最近呼叫優先、門的各種
按鈕與遮擋、超載、開/關門失敗、安全迴路斷開後自動找樓層、上電在兩層之間、
壓到下極限時往上找樓層、運行逾時、感測器漏訊號/同時 ON、超越極限、
運行中門鎖脫開、再平層、2～8 層、以及隨機乘客壓力測試（檢查每位乘客都能
送達，且每個呼叫燈熄滅時電梯確實停在該樓、方向正確、門正在開）。

執行（Linux / macOS / WSL，需要 `git gcc make autoconf automake flex bison python3`）：

```bash
cd sim
python3 -m unittest -v
```

第一次執行會自動下載並編譯 matiec（約 1～2 分鐘）。
