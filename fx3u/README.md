# 4 層電梯 — 三菱 FX3U 階梯圖版

把 [ST 版](../README.md) 的電梯控制改寫成三菱 **FX3U 階梯圖**：共 **170 個梯級、730 個指令**，
功能完全相同（集選控制、門控制、安全保護、上電找樓層、再平層、7 種故障碼）。

這份階梯圖和 ST 版跑的是**同一套 42 項模擬測試**（含故障注入與隨機乘客壓力測試），
另外在 200 次隨機乘客模擬（約 9000 位乘客）中全部送達、沒有發生故障。

## 硬體

- PLC：**FX3U-48MR/ES** 以上（需要輸入 24 點 X0~X27、輸出 24 點 Y0~Y27；FX3U-32M 點數不夠）
- 軟體：GX Works2（或 GX Developer）
- 馬達上升/下降接觸器、開門/關門接觸器必須在外部做**硬體互鎖**；
  負載電流較大時請經過中間繼電器，不要直接由 PLC 輸出點驅動。

## 軟元件分配

全部使用一般型（非停電保持）軟元件，停電再上電會從「初始化」重新開始。

| 軟元件 | 用途 |
|---|---|
| M101~M104 | 車廂呼叫記憶 1F~4F |
| M111~M113 / M122~M124 | 上呼記憶 1F~3F / 下呼記憶 2F~4F |
| M131~M134 | 各樓有任何呼叫 |
| M141~M144 | 目前在 1F~4F（由 D0 比較而來） |
| M150 | 在平層區（恰好一個平層感測器 ON） |
| M160 / M161 / M162 | 上方有呼叫 / 下方有呼叫 / 最近的呼叫在上方 |
| M170 / M171 / M172 | 本層有上呼 / 下呼 / 車廂呼叫 |
| **M200~M210** | **狀態**（同時只有一個 ON，見下表） |
| M220 / M221 | 服務方向 上 / 下（都 OFF = 無方向） |
| M222 / M223 | 運轉方向 上 / 下 |
| M230 | 服務本層（清除本層呼叫並開門） |
| M232 | 本次掃描已發生狀態轉移（每次掃描最多轉移一次） |
| M240~M245 | 故障偵測 |
| C0 / C1 | 關門失敗次數 / 再平層次數 |
| D0 / D1 / D2 | 目前樓層 / 故障碼 / 平層感測器所在樓層 |
| D6 / D7 | 上方 / 下方最近的呼叫樓層 |

完整清單與註解見 [devices.csv](devices.csv)。

### 狀態

| 狀態 | 說明 | 離開條件 |
|---|---|---|
| M200 初始化 | 上電後等 1 秒 | 在平層區 → 待命（門沒關 → 開門停留）；不在 → 找樓層 |
| M201 找樓層 | 先關門，再低速往下找樓層 | 找到樓層 → 停車，停妥後開門 |
| M202 待命 | 決定方向 | 本層有呼叫 → 開門中；有方向 → 起動延遲 |
| M203 開門中 | Y3 開門 | 開門到位 → 開門停留；8 秒未到位 → 故障 6 |
| M204 開門停留 | 停留 3 秒 | 時間到或關門鈕 → 關門中 |
| M205 關門中 | Y4 關門 | 到位 → 待命；遮擋/開門鈕/超載 → 開門中；逾時 3 次 → 故障 7 |
| M206 起動延遲 | 0.5 秒 | → 運行 |
| M207 運行 | Y0 或 Y1 | 到達要停的樓層 → 停車 |
| M208 停車 | 煞車 0.5 秒 | 在平層區 → 待命；滑出 → 再平層 |
| M209 再平層 | 低速反方向 | 回到平層區 → 停車 |
| M210 故障 | 全部停止、清除呼叫 | 故障 1 自動恢復；其他按復歸鈕 X27 |

**每個轉移梯級都串了 M232 的 b 接點**，並在轉移時 SET M232。
這樣一次掃描最多只會轉移一次，後面梯級不會在同一次掃描接著又轉移
（這是用 SET/RST 寫狀態機時最常見的錯誤）。

## 計時器（要調整時間就改設定值）

FX3U 的 T0~T199 是 100 ms 計時器：K30 = 3 秒。

| 計時器 | 設定值 | 用途 |
|---|---|---|
| T0 | K10（1 秒） | 上電等待輸入穩定 |
| T1 | K80（8 秒） | 找樓層前關門逾時 |
| T2 | K80（8 秒） | 開門逾時 → 故障 6 |
| T3 | K30（3 秒） | **開門停留時間** |
| T4 | K80（8 秒） | 關門逾時（重開重試） |
| T5 | K5（0.5 秒） | 起動延遲 |
| T6 | K5（0.5 秒） | 煞車延遲 |
| T7 | K150（15 秒） | 高速運行時間限制（每到一層重新計時）→ 故障 2 |
| T8 | K300（30 秒） | 低速運行時間限制 → 故障 2 |
| C0 | K3 | 關門連續失敗 3 次 → 故障 7 |
| C1 | K3 | 連續再平層 3 次仍失敗 → 故障 3 |

## 故障碼（D1）

| 碼 | 原因 | 復歸 |
|---|---|---|
| 1 | 安全迴路開路 / 緊急停止（X24 OFF） | 恢復後自動重新初始化 |
| 2 | 運行逾時（馬達、皮帶或感測器故障） | 按 X27 |
| 3 | 平層感測器同時 ON、樓層順序錯誤、再平層失敗 | 按 X27 |
| 4 | 碰到上/下極限 | 按 X27 |
| 5 | 運行中關門到位消失，或開門到位與關門到位同時 ON | 按 X27 |
| 6 | 開門失敗 | 按 X27 |
| 7 | 關門失敗 | 按 X27 |

## 用 GX Works2（直接讀取，不需要 GX Developer）

1. 新增專案：專案類型 **簡單工程（Simple Project）**、PLC 系列 **FXCPU**、機型 **FX3U/FX3UC**、
   語言 **階梯圖**。
2. 左側專案樹：程式 → **MAIN 按右鍵 → 從 CSV 檔讀取（Read from CSV File）**，
   選 [gx-works2/MAIN.csv](gx-works2/MAIN.csv)。
3. **全域軟元件註解按右鍵 → 從 CSV 檔讀取**，選 [gx-works2/COMMENT.csv](gx-works2/COMMENT.csv)。
4. 轉換（F4）確認沒有錯誤，對照 [LADDER.md](LADDER.md) 檢查後存檔。

這兩個檔案是 UTF-16 編碼，繁體中文的註解和每個梯級的說明（行間聲明）都會一起讀進去。
檔案格式照 GX Works2 自己匯出的 CSV（UTF-16、Tab 分隔，欄位標題取自簡體中文版的實際匯出檔）。
如果你的 GX Works2 是其他語言版本而出現格式錯誤：在 MAIN 按右鍵 → **寫入 CSV 檔（Write to CSV File）**
匯出目前的程式，把檔案前 3 列傳給我，我改成你那個版本的標題。

GX Works2 也可以開啟 GX Developer 的 .gpj 專案：**Project → Open Other Data → Open Other Project**
（開啟其他格式資料 → 開啟其他專案）。

## 用 GX Developer（.gpj 專案）

.gpj 是 GX Developer 的專案檔，屬於三菱不公開的二進位格式，只能由 GX Developer 自己產生。
所以這裡提供可以**匯入**的 CSV，匯入後存檔就是一般的 .gpj 專案，不需要手動輸入 1005 步程式：

1. 新增專案（Project → New project）：PLC series **FXCPU**、PLC type **FX3U(C)**、
   Program type **Ladder**。
2. **Project → Import file → Import from TEXT, CSV format file**，選
   [gx-developer/MAIN.csv](gx-developer/MAIN.csv)，資料種類選程式（清單 / List）。
   - 這個選單由 GX Developer 光碟上的 **GX Converter** 提供；看不到這個選單就是還沒安裝。
   - 若出現設定畫面：分隔符號選逗號（Comma）、文字以雙引號括住；資料從第 4 列開始（前 3 列是標題）。
3. 用同一個選單匯入 [gx-developer/COMMENT.csv](gx-developer/COMMENT.csv)，資料種類選註解（Comment）。
   這個檔案是 Big5 編碼，給繁體中文 Windows 用；註解出現亂碼時可以跳過這一步，不影響程式。
4. 轉換（F4），對照 [LADDER.md](LADDER.md) 檢查階梯圖，然後存檔（Project → Save）
   —— 這時就得到 .gpj 專案。
5. 寫入 PLC（Online → Write to PLC）。

匯入失敗或格式不符時（不同語言版本的 GX Developer，CSV 標題列可能不同）：

- 在你的 GX Developer 隨便寫兩三行程式，用 **Project → Export file → Export to TEXT, CSV format file**
  匯出成 CSV，把檔案前幾行傳給我，我照你的版本格式重新產生 MAIN.csv。
- 或者切換到清單（List）顯示，照 MAIN.csv 的「Instruction」與「I/O(Device)」欄逐條輸入
  （例如 `LD X027`、`MOV K0 D2`）。

兩種 CSV 都由 `sim/export_gx.py` 從 [elevator_fx3u.txt](elevator_fx3u.txt) 自動產生，
產生後會讀回來逐條比對，確認和階梯圖完全相同；X/Y 寫成三位數（X000、Y027），
和 GX Developer 的顯示方式一致。這裡沒有 GX Developer 可以實際測試匯入，
如果遇到問題請告訴我畫面上的訊息。

## 手動輸入（不能匯入時）

1. 新增專案：簡單工程（Simple Project）、PLC 系列 **FXCPU**、機型 **FX3U/FX3UC**、
   語言 **階梯圖（Ladder）**。
2. 對照 [LADDER.md](LADDER.md)（或 ladder.html）逐一輸入梯級。在階梯圖編輯畫面可以直接用
   鍵盤輸入指令再按 Enter，例如 `LD X0`、`AND M239`、`SET M101`、`LD= D0 K1`、
   `OUT T3 K30`、`MOV D2 D0`，順序照 [elevator_fx3u.txt](elevator_fx3u.txt)。
   同一梯級有好幾個輸出時，照圖在右側畫成並聯。
3. 軟元件註解照 [devices.csv](devices.csv) 輸入（可省略，但有註解比較好除錯）；
   綠色的說明文字可輸入成「宣告」。
4. 轉換（F4）後寫入 PLC。

本程式沒有使用 MPS/MRD/MPP 分支，每個梯級都是「一組接點 → 一個或多個輸出」，手動輸入比較不容易出錯。

## 上機前先用模擬測試

GX Works2 內建模擬功能（GX Simulator2）可以不接 PLC 先測試：

1. 開始模擬後，用軟元件測試（Modify Value）把 **X24、X25、X26（安全迴路、上下極限）設為 ON**、
   **X12（1F 平層）ON**、**X17（關門到位）ON**。
2. 1 秒後 M202（待命）ON、Y27（服務中）ON、D0 = 1。
3. 按一下 X2（車廂 3F）：Y12 亮、M220（方向上）ON、約 0.5 秒後 Y0（上升）ON。
4. 依序：X12 OFF → X13 ON → X13 OFF（經過 2F）→ X14 ON（到達 3F）：
   Y0 OFF，約 0.5 秒後 Y3（開門）ON。
5. 先 X17 OFF、再 X16（開門到位）ON：3 秒後 Y4（關門）ON；
   接著先 X16 OFF、再 X17 ON → 回到待命（M202）。

模擬時門與平層訊號要自己依實際順序切換，否則會進入故障（這正是保護功能）：

- X16 與 X17 同時 ON → 故障 5；跳過 2F 直接讓 X14 ON → 故障 3
- 上升中每一層要在 15 秒內切換到下一層的平層訊號，否則故障 2
- Y3 ON 後 8 秒內要讓 X16 ON，否則故障 6；Y4 ON 後 8 秒內要讓 X17 ON，否則重新開門
- 進入故障後（Y7 亮、D1 = 故障碼），先把輸入恢復正常，再按一下 X27 復歸

## 改成其他樓層數

以 5 層為例：需要 FX3U-64M 以上（輸入 32 點）；每多一層要增加的梯級有：按鈕登記、
各樓有呼叫、目前樓層比較、上/下方最近呼叫、本層上呼/下呼/車廂呼叫、清除呼叫、
平層感測器（含「兩個以上同時 ON」）、按鈕燈。邏輯都和現有樓層相同，照樣複製即可。

## 模擬驗證方式

`sim/fx3u.py` 是依 FX3U 指令動作寫成的指令表模擬器（掃描開始讀 X、由上而下執行、
END 後輸出 Y；計時器在執行 OUT T 時更新）。它會先檢查程式：

- 雙重線圈（同一個 Y/M/T/C 用了兩次 OUT）
- 軟元件超出範圍或用到停電保持區
- 讀取了從來沒有被寫入的軟元件（打錯編號）
- LD 與 ANB/ORB 不平衡

然後接上與 ST 版相同的電梯物理模型與測試（測試名稱結尾 `FX3U`）：

```bash
cd sim
python3 -m unittest -v
```

模擬器不是三菱官方軟體，上機前仍請先用 GX Works2 模擬或空載測試確認。
